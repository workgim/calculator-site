## 1. 네이버가 구글과 다른 점 (먼저 알아둘 것)

| 구분 | 구글 | 네이버 |
|------|------|--------|
| 새 사이트 발견 | 봇이 알아서 크롤링 | **자동으로 안 함.** 서치어드바이저에 등록·소유확인·사이트맵 제출·수집요청을 해야 색인 시작 |
| 크롤러 | Googlebot | **Yeti** (User-agent: `Yeti`) |
| 검색결과 구성 | 웹 문서 위주 | 통합검색(블로그·카페·지식iN·뷰·플레이스 등 자체 서비스 비중 큼). 다만 **웹사이트/웹문서 수집 영역이 확대되는 추세** |
| 랭킹 개념 | 페이지 단위 품질·링크·의도 | **적합도 + 인기도 + 신뢰도** 3축. 출처 단위 신뢰(C-Rank), 문서 단위 품질(D.I.A / D.I.A+) |
| 사이트맵 | 여러 개 자유 | **사이트당 1개 권장**, 여러 개면 각각 따로 제출 |
| 피드 | 선택 | **RSS/Atom 피드 제출** 권장 |

핵심: **네이버는 "등록해야 보인다."** 한국 사용자 검색의 상당 부분이 네이버이므로 등록은 필수.

## 2. 네이버 랭킹 요소 (개념)

정확한 공식은 비공개. 공개된 개념 수준에서:

- **적합도(relevance)**: 검색어와 문서 내용의 일치. title·본문·대표이미지·문서 구조가 주제를 분명히 드러내는가.
- **인기도(popularity)**: 클릭·체류·재검색 등 사용자 반응.
- **신뢰도(reliability)**: 출처의 일관성·전문성, 광고성/과장/낚시가 아닌가.
- **C-Rank**: 특정 주제에 대해 그 출처(사이트/블로그)가 **꾸준히 쌓아온 맥락과 신뢰**. → 한 주제(예: 생활 계산)를 꾸준히 다루는 것이 유리.
- **D.I.A / D.I.A+**: 문서 자체의 품질·정보성·**직접 경험/구체성**, 사용자가 선호하는 문서 패턴 학습.

계산기 사이트에 적용:
- 계산기별로 **직접 쓴 설명·예시·근거 출처**를 넣는다(빈 위젯 페이지 금지 — [12-page-structure.md](./12-page-structure.md) §5).
- "생활 계산기"라는 주제를 일관되게, 페이지를 꾸준히 늘린다.
- 과장·낚시 title 금지(신뢰도).

## 3. 구현 매핑표 (요구사항 → 코드 위치)

가이드가 바뀌면 "권장값"을 고치고 "구현 위치"를 수정한다.
공통 항목(title, description, canonical, 모바일, HTTPS, sitemap.xml, 404, 구조화 데이터 등)은
[20-seo-google.md](./20-seo-google.md) §3 매핑표를 그대로 따른다. **아래는 네이버 때문에 추가로 필요한 것**만.

배포 도메인: `https://calculator-site-lilac.vercel.app`

| # | 항목 | 권장값 / 규칙 | 구현 위치 | 현재 상태 |
|---|------|----------------|-----------|-----------|
| N1 | 소유확인 메타태그 | `<meta name="naver-site-verification" content="…">` | `src/config/site.ts` `verification.naver` → `Head.astro` (값 있을 때만 출력) | ✅ 소유확인 완료 |
| N2 | Open Graph 태그 | og:title/description/image/url — 네이버가 미리보기에 적극 사용, 대표 이미지 필수 | `Head.astro` + `public/images/og-default.png` (1200×630) | ✅ |
| N3 | robots.txt Yeti 허용 | `User-agent: *`/`Yeti` `Allow: /` + `Sitemap:` 절대경로 | `public/robots.txt` (Yeti 명시함) | ✅ |
| N4 | 사이트맵 | 1개로 유지, 서치어드바이저 제출 | `@astrojs/sitemap` → `/sitemap-index.xml` | ✅ 제출 완료 |
| N5 | RSS/Atom 피드 | 신규·업데이트 페이지 피드, 서치어드바이저 제출 | `@astrojs/rss` → `src/pages/rss.xml.ts` | 나중 (설명 글 쌓이면) |
| N6 | `<link rel="alternate" type="application/rss+xml">` | RSS 도입 시 head 추가 | `Head.astro` | 나중 |
| N7 | 모바일 대응 | 반응형(동일 URL), "모바일 친화도" 통과 | `global.css` — [30-design-guide.md](./30-design-guide.md) | ✅ |
| N8 | 웹 표준 | 유효한 HTML, "웹 표준 검증" 통과 | 전역 마크업 (Astro 빌드 유효 HTML) | ⏳ 서치어드바이저 도구로 재확인 |
| N9 | 프로토콜/호스트 통일 | https 단일, canonical 일치 | Vercel(https 강제) + `canonical`(`site.ts`) | ✅ (`.vercel.app` 단일 호스트) |
| N10 | title/description | 낚시·과장 금지, 페이지 고유 | `Head.astro` (§20 §2 패턴 공유) | ✅ |
| N11 | 대표 이미지 | 페이지별 대표 이미지(없으면 기본 OG) | 현재 전 페이지 기본 OG 공용 | ✅ (기본), 페이지별은 나중 |

## 4. 서치어드바이저 등록 절차

### 완료 (2026-09-07)

- 사이트 등록 `https://calculator-site-lilac.vercel.app`, **HTML 태그** 방식 소유확인 완료
  (코드: `src/config/site.ts` `verification.naver`).

### 남은 것 / 정기

1. **웹페이지 수집 요청**: 요청 > 웹페이지 수집 → 새 계산기 URL 등록. **하루 약 50 URL 한도**.
2. **진단 도구**: 검증 > 웹 표준 검증 / 모바일 친화도 실행, 경고 정리.
3. **RSS 제출**: 피드 도입(N5) 후.
4. 색인까지 보통 **1~4주**.
5. 커스텀 도메인 연결 시: 새 호스트로 사이트 다시 등록(구 호스트도 남겨두면 유입 데이터가 잡힌다).

## 5. 콘텐츠 권장 (네이버 관점)

- **원본성**: 다른 사이트 설명 복붙 금지. 공식 출처를 참고하되 문장은 직접 쓴다.
- **구체성·경험**: "이렇게 입력하면 이런 결과" 예시를 숫자로. 단순 공식 나열보다 낫다.
- **주제 일관성**: 생활 계산이라는 축을 유지하며 페이지를 꾸준히 추가(C-Rank).
- **신뢰 신호**: 근거(법령·공공기관) 링크, 최종 업데이트 날짜 표기, 운영자 소개(About), 개인정보처리방침.
- **낚시 금지**: title과 내용 불일치, 과장("무조건", "100% 정확") 표현 지양 → 신뢰도 하락.
- **광고 과다 금지**: 본문보다 광고가 먼저 보이는 배치 지양(사용자 반응 악화 → 인기도 하락). 광고 규칙은 나중에 `41-ads-adsense.md`.

## 7. 구글과 공유하는 부분 (중복 구현 안 함)

아래는 [20-seo-google.md](./20-seo-google.md)에서 이미 정의됨. 네이버도 동일하게 혜택:
`<html lang>`, utf-8/viewport, title/description, canonical, `sitemap.xml`, `robots.txt` 기본,
시맨틱 마크업/`h1` 1개, 이미지 `alt`, 내부 링크, HTTPS, 실제 404, 반응형, 성능(CWV).

→ **SEO 구현체는 하나.** 이 문서는 그 위에 "네이버라서 추가로 필요한 것"만 얹는다.
