## Part 1. 공통 프레임워크

### 1.1 원칙 (2026)

- 키워드 반복이 아니라 **검색 사용자의 문제를 실제로 해결**하는 콘텐츠. ([20-seo-google.md](./20-seo-google.md) §1, §5)
- FAQ는 "리치 결과"를 노리지 않는다 — 2026-05 이후 FAQ 리치결과는 일반 노출 안 됨. **실제 질문에 답하는 본문**으로만 가치가 있다.
- 모든 계산 결과·표는 우리 `src/lib/*.ts` 함수로 **빌드 시 계산**한다. 손으로 숫자를 적지 않는다 → 요율·공식이 바뀌면 표가 자동으로 맞는다.
- 페이지는 계속 가벼워야 한다. 표/텍스트가 늘어도 Lighthouse 100·CLS 0 유지 (이미지 없음, 인라인 JS 최소).

### 1.2 공통 페이지 틀

모든 계산기 페이지는 `CalculatorLayout` 안에서 아래 순서를 따른다. **굵은 항목**이 이번 작업으로 새로 채우는 부분.

| 순서 | 섹션 | 태그 | 비고 |
|------|------|------|------|
| 1 | 이동 경로 | Breadcrumb | 자동 |
| 2 | 계산기 이름 | `<h1>` | 자동 (`calculator.title`) |
| 3 | 한 줄 소개 | `<p class="lead">` | 자동 (`shortDescription`) |
| 4 | 계산기 UI | `<form>` + 결과 | 페이지 |
| 5 | 광고 자리 | AdSlot | 자동 |
| 6 | **이 계산기는 무엇을 계산하나요** | `<section><h2>` | 계산기의 역할 2~4문장 |
| 7 | **계산에 사용되는 용어** | `<section><h2>` + `<dl>` 또는 표 | 핵심 용어 3~6개 정의 |
| 8 | **계산 방법** | `<section><h2>` | 공식 + 단계. (기존 "계산 방법" 확장) |
| 9 | **계산 예시** | `<section><h2>` | 실제 입력 → 결과 1~2개, 문장으로 서술 |
| 10 | **자주 찾는 값** | `<section><h2>` + 표 | ★ SEO 핵심. lib 로 계산한 표 (§1.4) |
| 11 | **자주 묻는 질문** | `<section><h2>` + `<details>` | 실제 검색 질문 4~6개 (§1.5) |
| 12 | 관련 계산기 | `<nav>` | `related` 필드 기반 (§1.6) |
| 13 | 최종 업데이트 날짜 | 자동 | |

> 6~11번은 **계산기 유형에 따라 비중을 다르게** 한다 (§1.3). 모든 페이지를 같은 분량으로 채우지 않는다.

### 1.3 유형별 비중

| 유형 | 큰 비중 | 작은 비중 | 해당 계산기 |
|------|---------|-----------|-------------|

### 1.4 "자주 찾는 값" 표 — 구현 방법

- 각 계산기 페이지 `.astro` 의 **frontmatter(빌드 타임)** 에서 해당 `lib` 함수를 호출해 배열을 만들고 `<table>` 로 렌더.
- 예: `salary-net.astro`
  ```ts
  import { calcSalary } from '../../lib/salary';
  const rows = [24_000_000, 28_000_000, 30_000_000, /* ... */]
    .map((annual) => ({ annual, ...calcSalary({ annualSalary: annual }) }));
  ```
- 표의 각 행 링크: 가능하면 `?` 쿼리로 계산기 프리필 (예: `/calc/salary-net?salary=40000000`). 프리필 기능은 별도 작업 — 없으면 표만.
- 표 아래에 "표의 값은 기본 조건(비과세 월 20만원, 부양가족 1명 등) 기준이며, 위 계산기에서 조건을 바꿔 계산하세요." 한 줄.

### 1.5 FAQ

- 계산기당 **4~6개**. 실제로 사람들이 검색창에 치는 질문 형태로.
- `<details><summary>질문</summary><p>답변</p></details>` (JS 0). 스타일은 `global.css` 에 `.faq` 추가.
- 답변은 2~4문장. 필요하면 본문 섹션으로 링크.
- `FAQPage` JSON-LD 는 **넣지 않는다** (리치결과 없음, 유지보수만 늘어남). 결정 근거는 [20-seo-google.md](./20-seo-google.md) §4.

### 1.6 내부 링크 (`related` 필드 도입)

- `Calculator` 인터페이스에 `related?: string[]` 추가 (slug 배열, 2~4개, 카테고리 교차 허용).

  - 연 나이와 만 나이 차이 — 병역·청소년보호법 등은 연 나이
  - 생일 전/후 나이 계산 예시
  - 계산 예시 — "1995년 9월 10일생은 오늘 기준 만 ○○세"
  - 자주 묻는 질문
- **자주 찾는 값 표**: 생략 (연도별 "○○년생 만 나이" 표는 매년 갱신 부담 → 계산 예시로 대체). 대신 "출생연도 → 올해 기준 만 나이/연 나이" 미니 표를 lib 로 오늘 날짜 기준 생성해도 됨(선택).
- **FAQ**
  - 지금 만 나이로 몇 살인가요?
  - 만 나이와 연 나이는 어떻게 다른가요?
  - 빠른 년생은 어떻게 계산하나요?
  - 술·담배 구입 기준 나이는 만 나이인가요? (연 나이임을 안내)
  - 국제 나이와 같은가요?
- **related**: `dday`, `date-add`
- **타깃 키워드**: 만 나이 계산기 / 만나이 / 나이 계산 / 연 나이 / 나이 계산기

### percentage — 퍼센트 계산기

- **URL**: `/calc/percentage`

- **description**: `A의 B%, A는 B의 몇 %, 증가율·감소율, 할인율을 계산합니다. 50000원의 20%, 할인가 계산 등 예시 제공.`

  - A는 B의 몇 %인가요? — 예시
  - 몇 % 증가했나요? — 예시(50,000 → 60,000 은 20% 증가)
  - 몇 % 감소했나요? — 예시
